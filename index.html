01 / Overview

Everything the band needs.
Nothing it doesn’t.

01

One shared show state

Keep the band aligned around what is playing now and what comes next, whether performers join from a native Apple client or a browser.

NOWNeon WeatherShared across the band

A shared queue built for change

Search Songs or Setlists beside the live Queue, then add, reorder, remove, or move any waiting Song to Next without hiding transport controls. Concurrent requests are serialized against authoritative state while the current performance continues uninterrupted.

Private space to prepare

High-contrast Preview makes private inspection unmistakable and puts Add Next or Add to Queue beside the Song. Chart appearance, Display Key, instrument, spelling, and capo remain local to the performer and device.

“Make it go. Make it dependable. Then earn the next layer.”

02 / Design philosophy

Calm under
stage pressure.

01

Local first

The show should not depend on a distant service. Performance data stays close, responsive, and under the band’s control.

02

Clear boundaries

Shared playback, Queue, and Performance Key remain authoritative for the Band. Preview, workspace, and Display Key remain personal to each performer and device.

03

Performance focused

High-frequency actions stay visible, confirm success, and recover cleanly. Large targets, readable charts, and quiet reconnection help musicians keep moving under stage pressure.

04

Earn the next layer

An experiment can succeed without becoming a feature. Audio, MIDI, lighting, and automation expand only when real hardware, rehearsals, and performances show that they make the system more dependable.

03 / Development journey

Built one reliable
layer at a time.

LiveStage Pro is moving from a working prototype toward a trusted show system through small, testable milestones.

Foundation

Local performance model

Established the core model for bands, songs, members, libraries, and setlists.

Connection

Shared live sessions

Connected Mac and browser clients around authoritative show state, with clear separation between shared performance and private preparation.

Native

iPhone, iPad, and Watch

Added native performer workspaces, local session discovery, queue and setlist tools, private Preview, and a compact Watch transport companion.

On stage

From demonstration to dogfooding

Repeated rehearsals and live shows now drive the design: safer Queue editing, unmistakable Preview, consistent transport controls, adaptable charts, quieter reconnection, and explicit recovery tools.

Beta hardening

Closing the gap through recovery and correctness

The iPad Host now covers the core local, hosting, and performer-join paths while the wider Apple client family gains stronger discovery, reconnection, chart, and audio-selection behavior. Successive code-review passes are hardening playback authority, content transactions, archive restore, and lifecycle recovery before the first small trusted-Wi-Fi beta.

05 / Current status

Active development

Stage-proven on Mac,
hardening for iPad beta.

LiveStage Pro has been the primary show system for nine paying 73 Paces gigs since August, progressing from shared charts, Queue, and transport into a larger part of the production workflow. For the last four shows, LiveStage Pro replaced Show Buddy Setlist for audio playback and now drives show lighting directly through Show Buddy Active for our setup. That field record remains the reference point as the same show model expands across the Apple platform.

The iPad Host now supports a fuller three-mode workflow: work locally, host a Band on the LAN, or join another LiveStage Pro Host as a performer. Joining hands shared show authority to the remote Host; leaving restores the prior local repertoire and stopped Queue. Mac and iPad Hosts, along with the native iPhone and iPad client, can discover nearby Sessions through Bonjour while retaining manual connection as a fallback.

Native client progress is increasingly about resilience rather than feature count. The iPad Host can check and re-advertise a healthy embedded Session after unlock, or recover a stopped Hosting runtime from its in-memory Queue before clients reconnect. Native performers can select an alternate recording for the next Play, retry failed PDF loads, and receive clearer discovery failures. Backing-track choice now stays synchronized across clients, and ChordPro layout has been refined across the performance surfaces.

Playback correctness has received another layer of protection. Play and Pause are now bound to the exact cued occurrence seen by the performer, so a delayed gesture from Mac, iPhone, iPad, WebClient, or Watch cannot start or pause a different Song after the Queue has advanced. Reconnection and recovery continue to apply the Host’s current state without replaying uncertain transport commands.

Several independent code-review and re-review passes have also driven deeper hardening. Critical and high-priority findings—and selected medium-priority items—have been addressed across server lifecycle, local-only control boundaries, archive validation, staged Song edits, recoverable Band and Library restore, and catalog transactions. Destructive content changes now retain recovery material where appropriate, while interrupted operations are resolved before active repertoire is loaded.

The next milestone remains a small trusted-Wi-Fi iPad Host beta. Automated coverage and source review are substantially stronger, but the candidate still needs repeat physical-device acceptance with real Band content, audio, MIDI, lighting, native and browser performers, interruption handling, unlock recovery, and off-device backup. The Mac remains the production Host until that evidence is complete.
